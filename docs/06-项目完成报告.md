# 项目完成报告（阶段一：基于 MongoDB 的问卷系统）

https://github.com/4a2b2/dbms_project.git

## 一、项目目标

按初始需求实现一个简化版在线问卷系统：注册用户创建问卷并通过链接分发，用户（可匿名）逐题填写，创建者查看统计结果。重点考察 MongoDB 数据库设计、后端逻辑、跳转与校验建模、AI 工具使用的规范性。

## 二、系统设计

### 2.1 分层结构

```
Controller（HTTP）  AuthController / SurveyController / FillController / PageController
Service（业务）     AuthService / SurveyService / ResponseService / StatsService
Core（纯逻辑，可扩展） 题型处理器注册表、条件算子注册表、跳转引擎、答案校验器
Repository（持久）  Spring Data MongoDB 三个 Repository
Model（领域文档）   Survey / Question / Option / LogicRule / User / SurveyResponse / Answer
```

- **Core 层与 Spring 解耦程度可控**：`LogicEngine`、`ConditionOperators`、各 `QuestionTypeHandler` 都不依赖数据库，可单独做单元测试（本次测试中 `LogicEngineTest`、`ConditionOperatorsTest` 就是无 Spring 上下文运行的）。
- **两类接口分离**：管理端 `/api/surveys/**`（必须登录 + 归属校验）与填写端 `/api/s/{shareCode}/**`（支持匿名），互不干扰。
- **入口分层拦截**：`AuthInterceptor` 只负责"解析 token"，"是否必须登录"由各 Service 决定，因此同一套填写接口既能匿名也能登录填写。

### 2.2 页面（5 个）

| 页面 | 说明 |
|---|---|
| `login.html` | 登录/注册一体，token 存 localStorage |
| `surveys.html` | 我的问卷列表：新建、发布、关闭、删除、复制分享链接、进入编辑/统计 |
| `edit.html` | 编辑器：基本信息、设置（匿名/多次/截止时间）、题目增删排序、选项、约束、跳转规则；发布后题目区只读 |
| `fill.html` | 填写页：逐题渲染、即时校验、按规则跳转、草稿续填、提交 |
| `stats.html` | 统计页：选项条形图、数字平均/最小/最大、文本列表 |

前端为原生 JS + fetch，`static/js/common.js` 统一封装请求（自动带 token，401 跳登录）。

## 三、MongoDB 设计

三个集合：`users` / `surveys` / `responses`（完整字段与索引见《系统说明与数据库设计》）。

核心决策：

1. **题目、选项、约束、跳转规则内嵌进 `surveys`**：问卷与其内容是不可分割的聚合，永远整卷读写；内嵌后取整卷只查一次，数组顺序即答题顺序，也不必跨集合维护顺序一致性。
2. **答案内嵌进 `responses`**：一份答卷是一份独立快照，一条记录一次写入；`answers[]` 用 `{qid, optionIds, text, number}` 统一承载四种题型，加题型不改答卷结构。
3. **答卷引用问卷**（`surveyId`）而非内嵌问卷：避免问卷改动要同步所有答卷副本造成的不一致；问卷是"可变的定义"，答卷是"已发生的记录"。
4. **谨慎冗余**：只在聚合内部内嵌，不做跨集合冗余（不在答卷里存问卷标题）。
5. **索引**：`users.username` 唯一、`surveys.shareCode` 唯一、`surveys.ownerId`、`responses.surveyId`。
6. **`schemaVersion`**：为第二阶段结构迁移预留。

**为什么不用关系数据库**：题目/选项/约束/规则的结构随题型变化（不同题型字段不同、选项数不定、约束键不同），关系库需要 `questions`/`options`/`constraints`/`logic_rules` 多表 + 可空列或 EAV 表，加题型即改表；答卷的多态答案同样如此。文档模型让"一份问卷一段结构"自然表达，扩展时不改 schema。

## 四、跳转设计

- 规则数据存于问卷文档 `logic[]`，结构为 `{id, when:{qid, op, value}, then:{action, targetQid}}`，**不写死在代码里**。
- `when.op` 由算子注册表解释（`eq`/`in`/`contains`/`containsAll`/`gt`/`gte`/`lt`/`lte`/`between`），支持"按单选结果跳转、按多选结果跳转、按数字内容跳转"三类需求。
- `nextQuestion`：按规则顺序取第一条命中 → `end` 结束 / `jumpTo` 目标题；无命中则顺序下一题，最后一题结束。
- 保存问卷时 `validateRules` 校验规则合法性，并限定**阶段一只能向后跳**，从设计上排除环；第二阶段的向前跳只需放宽该校验并给复核循环加访问计数。

## 五、校验设计

三层防线：

| 层 | 位置 | 内容 |
|---|---|---|
| 前端 | `fill.html` | 按 `constraints` 即时提示（必答、多选数量、文本长度、数字范围与整数） |
| 保存单题 | `ResponseService.saveAnswer` + `AnswerValidator` | qid 存在、选项存在且去重、单选恰好 1 项、`minSelect`/`maxSelect`、`minLength`/`maxLength`、`min`/`max`/`integerOnly`；同时清理该题之后的旧答案防脏数据 |
| 提交 | `ResponseService.submit` | 从第一题沿跳转路径逐题复核，路径上的必答题未答即 400 |

结构校验（保存/发布时）：qid 唯一、oid 唯一、标题非空、题型约束自洽（如 `maxSelect ≤ 选项数`、`min ≤ max`）、跳转规则合法。

## 六、AI 使用过程（摘要，逐条记录见《AI 使用日志》）

- **AI 帮了什么**：生成项目骨架、三集合 Schema 初稿、四种题型处理器与算子注册表的实现、全部 Service/Controller、五个页面与共享 CSS/JS、集成测试与本文档初稿，约 80% 的代码量。
- **AI 做错了什么**：① `th:inline` 脚本里的 JS 二维数组 `[[...]]` 被 Thymeleaf 当内联表达式，导致编辑页 500；② 测试依赖版本 `6.0.0` 在镜像不存在；③ 建议内嵌 Mongo 不写版本号，实测直接启动失败；④ 建模时漏掉"回改前面题目导致后续路径外答案残留"这一场景。
- **自己改了什么**：把题型标识从枚举改为字符串 + 处理器注册表（坚持"不写死"）；把独立 `questions` 集合改为内嵌数组；补脏数据清理逻辑与"只能向后跳"限定；补 `schemaVersion`；修复页面 500（改用隐藏域传值）与测试配置；逐条跑通测试并记录失败原因。

## 八、遇到的问题与解决

| 问题 | 现象 | 解决 |
|---|---|---|
| Thymeleaf 内联表达式冲突 | 编辑页 500：`Could not parse as expression: "'eq', '选中']..."` | 去掉 `th:inline`，变量改用隐藏域 `th:value` 传给脚本 |
| 测试依赖版本不存在 | `de.flapdoodle...spring31x:6.0.0` 在 Maven 镜像找不到 | 改为 `4.11.0` |
| 内嵌 Mongo 未指定版本 | `IllegalStateException: Set the de.flapdoodle.mongodb.embedded.version property...` | 测试配置显式设置 `de.flapdoodle.mongodb.embedded.version: 6.0.5`，并用独立库名 `surveydb_test` |
| 改答前题后残留脏答案 | 改选后路径变化，旧答案仍在，统计被污染 | `saveAnswer` 删除该题及之后的旧答案 + 配套测试 |
| 跳转死循环风险 | — | 阶段一强制"只能向后跳"，天然无环 |
| 环境限制 | PowerShell 不支持 `&&`；Maven 本地仓库在沙箱可写范围外导致插件下载被拒 | 命令改用 `;` 连接；`mvn test` 在非沙箱模式下执行 |

## 九、第二阶段的扩展预留（为"不得推倒重做"做准备）

- **加题型**：新增 `QuestionTypeHandler` 实现类 + `@Component`，注册表自动收录，校验与统计自动接入；答卷结构（`answers[]`）无需改动。
- **加跳转条件**：`ConditionOperators.register(...)` 一行；规则文档结构不变。
- **结构变更**：`surveys.schemaVersion` 作为迁移依据，可对新旧文档做兼容读取。
- **旧功能兼容**：题目/逻辑内嵌、答案三值字段多态的设计，使得新增字段（如题目标签、题库引用）可作为可选字段追加，旧文档缺省即为默认值，不会导致旧数据不可读。
- **已知约束**：发布后题目结构锁定；第二阶段若要求"修改已发布问卷题目"，需要引入版本化（如 `questionsVersion`）或规则映射层，这一点已在此记录。
