# 项目完成报告（MongoDB 问卷系统 · 阶段一 + 阶段二）

https://github.com/4a2b2/dbms_project.git

## 一、项目目标

按课程要求实现一个简化版在线问卷系统：注册用户创建问卷并通过链接分发，填写者（支持匿名）逐题作答，创建者查看统计结果。重点考察 MongoDB 数据库设计、后端逻辑、跳转与校验建模、AI 工具使用的规范性。

阶段二依据《大作业一：需求变更》完成八项扩展：题目独立保存与复用、题目共享、修改题目不影响已建问卷、修改历史与恢复、同一题目多版本并存、查看题目使用情况、题库管理、跨问卷单题统计。扩展在不推倒阶段一实现的前提下完成，第一阶段的校验、跳转、统计与填写页逻辑未做逻辑改动。

## 二、系统设计

### 2.1 分层结构

```
Controller（HTTP）  AuthController / SurveyController / FillController / ItemController / PageController
Service（业务）     AuthService / SurveyService / ResponseService / StatsService / ItemService
Core（纯逻辑，可扩展） 题型处理器注册表、条件算子注册表、跳转引擎、答案校验器
Repository（持久）  User / Survey / SurveyResponse / QuestionItem / QuestionVersion 五个 Repository
Model（领域文档）   User / Survey / Question / Option / LogicRule / Settings
                    SurveyResponse / Answer / QuestionItem / QuestionVersion
Config（启动）      WebConfig（拦截器注册）、SchemaMigrationRunner（旧数据迁移）
```

- **Core 层与 Spring 解耦程度可控**：`LogicEngine`、`ConditionOperators`、各 `QuestionTypeHandler` 都不依赖数据库，可脱离 Spring 上下文单独测试。
- **两类接口分离**：管理端 `/api/surveys/**`、`/api/items/**`（必须登录 + 归属校验）与填写端 `/api/s/{shareCode}/**`（支持匿名），互不干扰。
- **入口分层拦截**：`AuthInterceptor` 只负责解析 token，"是否必须登录"由各 Service 决定，因此同一套填写接口既能匿名也能登录填写。
- **阶段二的新服务独立成型**：题库相关逻辑集中在 `ItemService`，`SurveyService` 只在其上完成"保存问卷时的引用解析"，避免职责混杂。

### 2.2 页面（6 个）

| 页面 | 说明 |
|---|---|
| `login.html` | 登录/注册一体，token 存 localStorage |
| `surveys.html` | 我的问卷列表：新建、发布、关闭、删除、复制分享链接、进入编辑/统计；顶部新增"题库"入口 |
| `edit.html` | 编辑器：基本信息、设置（匿名/多次/截止时间）、题目增删排序、选项、约束、跳转规则；发布后题目区只读；阶段二新增"从题库选择"面板与"题库 vN"版本徽标 |
| `fill.html` | 填写页：逐题渲染、即时校验、按规则跳转、草稿续填、提交（阶段二未改动） |
| `stats.html` | 统计页：选项条形图、数字平均/最小/最大、文本列表 |
| `library.html` | 题库页（阶段二新增）：我的题库/共享广场切换、新建与编辑题目、版本历史与恢复、使用情况、共享开关、跨问卷统计 |

前端为原生 JS + fetch，`static/js/common.js` 统一封装请求（自动带 token，401 跳登录）。

## 三、MongoDB 设计

五个集合：`users` / `surveys` / `responses` / `question_items` / `question_versions`。

### 3.1 阶段一的三集合

1. **题目、选项、约束、跳转规则内嵌进 `surveys`**：问卷与其内容是不可分割的聚合，永远整卷读写；内嵌后取整卷只查一次，数组顺序即答题顺序，也不必跨集合维护顺序一致性。
2. **答案内嵌进 `responses`**：一份答卷是一份独立快照，一条记录一次写入；`answers[]` 用 `{qid, optionIds, text, number}` 统一承载四种题型，加题型不改答卷结构。
3. **答卷引用问卷**（`surveyId`）而非内嵌问卷：避免问卷改动要同步所有答卷副本造成的不一致；问卷是"可变的定义"，答卷是"已发生的记录"。
4. **谨慎冗余**：只在聚合内部内嵌，不做跨集合冗余（不在答卷里存问卷标题）。
5. **索引**：`users.username` 唯一、`surveys.shareCode` 唯一、`surveys.ownerId`、`responses.surveyId`。
6. **`schemaVersion`**：阶段一预留，阶段二实际用于结构迁移。

### 3.2 阶段二新增的版本化模型

**`question_items`（题目条目）**：只存元数据，不存题目内容。

| 字段 | 说明 |
|---|---|
| `_id` | 条目 ID |
| `ownerId` | 创建者（索引） |
| `tags` | 标签数组，用于题库分类 |
| `shared` | 是否共享给其他用户 |
| `currentVersionId` | 当前版本指针 |
| `copiedFromItemId` | fork 来源条目（从共享题改造而来时记录） |
| `createdAt` / `updatedAt` | 时间戳 |

**`question_versions`（不可变版本）**：复合唯一索引 `{itemId:1, version:1}`。

| 字段 | 说明 |
|---|---|
| `_id` | 版本 ID |
| `itemId` | 所属条目（索引） |
| `version` | 版本号，从 1 递增 |
| `parentVersionId` | 上一版本 ID（v1 为 null），构成版本链 |
| `type` / `title` / `required` / `options` / `constraints` | 题目内容，与问卷内嵌字段一致 |
| `note` | 修改说明 |
| `createdAt` | 时间戳 |

**`surveys.questions[]`**：在原有内容字段之外新增 `itemId / versionId / version` 三个引用字段，其余字段成为**引用时刻的内容快照**，发布后固化。

### 3.3 关键设计决策

1. **版本不可变**：题目内容只能通过创建新版本演进，任何版本创建后永不修改。这是"修改题目不影响已做好的问卷"的根本保障——旧版本还在，引用它的问卷就有据可查。
2. **引用 + 快照双重记录**：问卷既记录引用的版本 ID，又内嵌完整内容。前者支撑使用情况追踪与跨问卷统计，后者让第一阶段的校验、跳转、统计、填写页零改动，也让问卷与答卷在数据上自洽。
3. **条目与内容分离**：条目只存归属与指针，内容全部在版本里，"当前内容"永远等于 `currentVersionId` 指向的版本，不存在两份真相。
4. **版本链而非线性覆盖**：`parentVersionId` 让每版知道从哪版改来；恢复旧版采用"以旧版内容创建最新版"而非回滚指针，历史链完整可追溯。
5. **索引设计**：`question_versions` 的复合唯一索引保证同一题目版本号不重复；`question_items.ownerId`、`question_versions.itemId` 支撑题库列表与版本查询；`surveys` 上无索引的 `questions.itemId` 查询用于使用情况，数据规模下可接受。

**为什么不用关系数据库**：题目/选项/约束/规则的结构随题型变化（不同题型字段不同、选项数不定、约束键不同），关系库需要 `questions`/`options`/`constraints`/`logic_rules` 多表 + 可空列或 EAV 表，加题型即改表；答卷的多态答案同样如此。文档模型让"一份问卷一段结构"自然表达，扩展时不改 schema。版本化也受益于此：版本文档直接复用题目结构，无需额外拆表。

## 四、核心逻辑

### 4.1 跳转

- 规则数据存于问卷文档 `logic[]`，结构为 `{id, when:{qid, op, value}, then:{action, targetQid}}`，**不写死在代码里**。
- `when.op` 由算子注册表解释（`eq`/`in`/`contains`/`containsAll`/`gt`/`gte`/`lt`/`lte`/`between`）。
- `nextQuestion`：按规则顺序取第一条命中 → `end` 结束 / `jumpTo` 目标题；无命中则顺序下一题，最后一题结束。
- 保存问卷时 `validateRules` 校验规则合法性，并限定**只能向后跳**，从设计上排除环。

### 4.2 校验

三层防线：

| 层 | 位置 | 内容 |
|---|---|---|
| 前端 | `fill.html` | 按 `constraints` 即时提示（必答、多选数量、文本长度、数字范围与整数） |
| 保存单题 | `ResponseService.saveAnswer` + `AnswerValidator` | qid 存在、选项存在且去重、单选恰好 1 项、`minSelect`/`maxSelect`、`minLength`/`maxLength`、`min`/`max`/`integerOnly`；同时清理该题之后的旧答案防脏数据 |
| 提交 | `ResponseService.submit` | 从第一题沿跳转路径逐题复核，路径上的必答题未答即 400 |

结构校验（保存/发布时）：qid 唯一、oid 唯一、标题非空、题型约束自洽、跳转规则合法。

### 4.3 问卷保存时的静默版本化（阶段二核心）

`SurveyService.resolveQuestions` 在保存问卷时逐题判定：

| 情况 | 处理 |
|---|---|
| 题目无 `itemId` 且勾选「添加到题库」 | 创建题库条目 + v1（新题入题库） |
| 题目无 `itemId` 且未勾选 | 仅属于本问卷，不入题库 |
| 引用题且内容未变 | 沿用该版本引用，不产生新版本 |
| 引用自己的题且内容变了 | 自动创建下一版本（`parent = 当前版本`），问卷引用新版本 |
| 引用别人的共享题且内容变了 | 自动 fork 为自己的新条目（记录 `copiedFromItemId`），原题不受影响 |

用户在编辑器里改题不需要理解版本概念，系统在保存时完成正确的事。内容比对覆盖题型、标题、必答、选项（按 `oid + text` 及顺序）、约束（键集相同后逐值比较，兼容 `Integer`/`Double` 差异）。

### 4.4 旧数据迁移

`SchemaMigrationRunner`（`ApplicationRunner`）启动时扫描 `schemaVersion < 2` 的问卷，为每道无引用的旧题创建条目 + v1（`note = "由旧版问卷迁移"`）并回填引用，置 `schemaVersion = 2`。迁移幂等：已带 `itemId` 的题跳过，重复执行不会产生新版本。

## 八、遇到的问题与解决

| 问题 | 现象 | 解决 |
|---|---|---|
| Thymeleaf 内联表达式冲突 | 编辑页 500：`Could not parse as expression` | 去掉 `th:inline`，变量改用隐藏域 `th:value` 传给脚本 |
| 测试依赖版本不存在 | `de.flapdoodle...spring31x:6.0.0` 在 Maven 镜像找不到 | 改为 `4.11.0` |
| 内嵌 Mongo 未指定版本 | `IllegalStateException: Set the de.flapdoodle.mongodb.embedded.version property...` | 测试配置显式设置 `de.flapdoodle.mongodb.embedded.version: 6.0.5`，并用独立库名 `surveydb_test` |
| 改答前题后残留脏答案 | 改选后路径变化，旧答案仍在，统计被污染 | `saveAnswer` 删除该题及之后的旧答案 + 配套测试 |
| 编辑器改题回顶部、误报空标题 | 任何操作都提示"存在标题为空的题目"并回到页首 | 结构性操作改为"标记脏 + 重渲染"，不再立即保存；`render` 保持滚动位置 |
| 只改标签也刷出版本 | 编辑表单总是提交全部内容字段 | `ItemService.update` 与当前版本做内容比对，真正不同才建版本 |
| 题库表单丢失选项 `oid` | 每次保存都重新生成 `oid`，内容比对永远不一致 | 表单选项保留 `{oid, text}`，并让非单选题始终提交约束（空对象可清空） |
| 测试中文乱码 | 7 个新增用例断言乱码并连锁失败 | MockMvc 请求体与响应统一 UTF-8（`writeValueAsBytes` / `getContentAsString(StandardCharsets.UTF_8)`） |
| 环境限制 | PowerShell 不支持 `&&`；Maven 本地仓库在沙箱可写范围外 | 命令改用 `;` 连接；`mvn test` 在非沙箱模式下执行 |

## 九、已知限制

- 跳转规则只允许向后跳，避免环；向前跳与循环需配合访问计数实现。
- 已发布问卷不支持修改题目结构；题库题目可随时改出新版本，供新问卷引用。
- 被问卷引用的题库条目禁止删除（返回 409），避免历史问卷失去溯源。
- 统计实时计算、不落库，适合当前数据规模；跨问卷统计需遍历引用该题目的答卷。
- 选择题跨版本不合并统计（选项 `oid` 可能随版本变化），只按版本分组展示；文本/数字题在题型一致时提供跨版本总览。
- JWT 密钥写在配置文件，部署时应改为环境变量。
