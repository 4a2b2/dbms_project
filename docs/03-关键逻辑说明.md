# 关键逻辑说明（阶段一）

## 1. 题型扩展机制（不把逻辑写死）

**问题**：四种题型的结构校验、答案校验、统计汇总差异很大，如果把 `if (type == "single") ... else if ...` 写进 Service，阶段二新增题型（如排序题、矩阵题、日期题）就要改多处分支代码。

**设计**：`core/question` 下定义处理器接口，四种题型各一个实现，Spring 自动注册进注册表。

```
QuestionTypeHandler (接口)
├── String type()                                    题型标识
├── void validateQuestion(Question q)                 保存问卷时校验题目结构
├── void validateAnswer(Question q, Answer a)         提交/保存答案时校验回答
└── Map<String,Object> summarize(Question, List<Answer>)  统计汇总
```

- `QuestionTypes`：字符串常量（`single` / `multiple` / `text` / `number`），**不用枚举**，这样新题型无需改公共类。
- `AbstractQuestionTypeHandler`：抽出 `unanswered()` 公共判断——三个值字段（`optionIds`/`text`/`number`）全为空视为未作答，此时若 `required=true` 直接报错。
- `QuestionTypeRegistry`：构造时注入 `List<QuestionTypeHandler>`，按 `type()` 建 `Map<String, Handler>`；未知题型抛 400。
- `AnswerValidator`：按题目 `type` 查注册表分发校验。

**扩展方式（阶段二）**：新增 `XxxQuestionHandler implements QuestionTypeHandler` 并声明 `@Component`，或在 `QuestionTypes` 加常量——注册表与校验入口零改动。新增题型专属约束键写在 `Question.constraints` 里，无需改文档结构。

## 2. 条件算子注册表（跳转条件不写死）

`core/logic/ConditionOperators` 用 `Map<String, BiPredicate<Answer, Object>>` 注册算子，构造器中一行一个：

| 算子 | 语义 |
|---|---|
| `eq` | 单选选中该选项；或数字等于该值 |
| `in` | 单选选中项 / 数字落在候选列表中 |
| `contains` | 多选包含指定选项 |
| `containsAll` | 多选包含列表中的全部选项 |
| `gt` `gte` `lt` `lte` | 数字比较 |
| `between` | 数字在 `[min,max]` 闭区间（值可为 `[min,max]` 数组或 `{min,max}` 对象） |

- 空答案一律返回 `false`（未作答不触发跳转）；未知算子抛 400。
- 新算子（如 `matches`、`notContains`）只需 `register(...)` 一行，规则文档无需改动。
- `core/Values` 统一处理"JSON 反序列化后同一数字可能是 Integer 或 Double、布尔可能是字符串"的问题，避免各算子重复类型判断。

## 3. 跳转逻辑引擎

数据来源是问卷文档里的 `logic[]`，**不写死在代码**。

```
nextQuestion(survey, response, justAnsweredQid):
  1. 若存在规则：从 response 取出 justAnsweredQid 的答案
     按 logic[] 顺序找第一条 when.qid == justAnsweredQid 且算子成立的规则
       then.action == "end"    → 返回 null（问卷结束）
       then.action == "jumpTo" → 返回 then.targetQid
  2. 无命中规则 → 返回数组中下一题的 qid；已是最后一题 → null
```

要点：
- **按规则顺序取第一条命中**：多条规则同时成立时行为可预测（先定义者优先）。
- `firstQuestion()` 返回题目数组第 0 题的 `qid`，作为默认入口。
- **阶段一无环保证**：`validateRules()` 强制 `targetQid` 在题目数组中的下标 > 条件题目下标，即"只能向后跳"，因此提交复核时不会死循环；同时校验规则 id 非空、条件/目标题目存在、算子已注册、动作是 `jumpTo`/`end`。
- 阶段二若要支持向前跳（回跳/循环），只需替换 `validateRules` 的这条限制并在复核循环中加入访问计数上限，`nextQuestion` 本身无需改动。

## 4. 答案校验设计

分三层，越早拦截越好：

1. **前端即时校验**（`fill.html`）：按 `constraints` 就地提示（如多选超限、非整数、必答未填），改动不提交请求。
2. **保存单题时校验**（`ResponseService.saveAnswer` → `AnswerValidator`）：后端权威校验，通过后才落草稿。
   - `qid` 必须存在；题型处理器校验答案（单选必须且只能 1 项且选项存在、多选去重且满足 `minSelect`/`maxSelect`、文本长度区间、数字有限且满足 `min`/`max`/`integerOnly`）。
3. **提交时全路径复核**（`ResponseService.submit`）：从 `firstQuestion` 开始沿跳转路径逐题走，路径上每题都要 `validateAnswer` 通过——**必答题哪怕前端被绕过、草稿里也没有，也会在提交时被拦下**。这一步同时保证"只校验实际走到的题"，被跳过的题即使必答也不要求作答。

**防止脏数据**：重新回答某题时，`saveAnswer` 会删除该题及之后的所有旧答案（`survey.indexOfQuestion(a.getQid()) >= answeredIndex`）。因为再次作答可能改变跳转路径（例：原先选 A 跳到第 5 题并答了 5、6，改选 B 后路径只剩第 3 题），不清除就会残留不在路径上的答案，污染统计。

**状态机**：答卷 `DRAFT → SUBMITTED`，已提交的答卷拒绝再次保存或提交（400）。

## 5. 草稿与续填

- 每次 `saveAnswer` 都立即落库（`responses` 文档随写随存），并把 `currentQid` 更新为下一题，因此中途关闭页面不丢进度。
- 登录用户 `start()` 时若存在自己的 `DRAFT` 答卷，直接返回该答卷并 `resumed=true`（前端据此回到 `currentQid` 继续）；匿名用户每次新建草稿，前端用 `localStorage['response_' + shareCode]` 记住 `responseId` 实现匿名续填。
- `allowMultiple=false` 时，已存在该用户的 `SUBMITTED` 答卷则 `start()` 返回 409。

## 6. 发布、分享与锁定

- `publish()`：校验草稿状态 → 至少一道题 → 结构校验 → 生成 `shareCode` → `status=PUBLISHED`。
- `shareCode`：8 位随机字符，字母表剔除了易混淆的 `i l o I L O 0 1`，生成时循环查重，`surveys.shareCode` 建唯一索引兜底。
- **发布后题目与逻辑结构锁定**（`update()` 拒绝改 `questions`/`logic`，报 400），但标题、说明、设置（是否匿名、是否允许多次、截止时间）仍可改。理由是已发出的链接对应的题目结构若被改动，已收集的答卷与统计会失去一致性。
- 未发布问卷的链接不对外可用：`getForFill()` 对非 `PUBLISHED` 返回 404、`CLOSED` 返回 400、超过 `settings.deadline` 返回 400。
- `close()`：仅 `PUBLISHED` 可关闭。
- `delete()`：删除问卷时级联删除 `responses` 中该问卷的答卷。

## 7. 权限与认证

- `AuthInterceptor` 拦截 `/api/**`：解析 `Authorization: Bearer <token>`，成功则把 `uid`、`username` 放进 request attribute；无 token 放行（由接口自行决定），token 无效直接 401。
- 管理端接口一律 `Auth.requireUid(request)`；问卷归属校验放在 `SurveyService.getOwned()`（不存在 404、非本人 403），所有管理操作都经过它，避免越权。
- 填写端接口故意不要求登录（支持匿名），是否允许匿名由问卷 `settings.allowAnonymous` 决定。
- 密码只存 BCrypt 哈希；JWT 为 HS256，密钥与有效期在 `application.yml`（生产应改用环境变量注入）。
- 错误统一由 `GlobalExceptionHandler` 输出 `{"error": msg}`，含 `@Valid` 参数校验、唯一索引冲突（409）、未知异常（500）。

## 8. 统计

`StatsService.stats(survey)` 只取该问卷 `SUBMITTED` 的答卷，对每道题把答案交给对应题型处理器的 `summarize()`：

| 题型 | 输出 |
|---|---|
| single | `total`（回答人数）、`options[{oid,text,count}]` |
| multiple | `total`（作答该题人数）、`options[{oid,text,count}]`（各选项被选次数） |
| text | `total`、`texts[]`（全部非空内容） |
| number | `total`、`average`、`min`、`max` |

统计**不落库**、不预聚合，按需实时计算（阶段一数据量下正确性优先）。新增题型只需实现 `summarize()` 即可自动出现在统计里。
