# 系统说明与数据库设计（版本 2）

## 1. 项目概述

基于 MongoDB 的在线问卷系统（类问卷星 / Google Forms）。注册用户创建问卷并通过分享链接分发，其他用户（可匿名）逐题填写，系统自动生成统计结果。

版本 2 在阶段一基础上增加题库：题目可独立保存、跨问卷复用、共享给其他用户，并以不可变版本的方式演进，修改题目不影响已经做好的问卷。

技术栈：

| 层 | 选型 |
|---|---|
| 数据库 | MongoDB 5.x/6.x（本地 localhost:27017，库名 `surveydb`） |
| 语言 / 框架 | Java 21 + Maven 3.9.4 + Spring Boot 3.3.5 |
| 持久层 | Spring Data MongoDB |
| 页面 | Thymeleaf + 原生 JavaScript（fetch），无前端框架 |
| 认证 | 自研 JWT（jjwt 0.12.6，HS256），密码用 spring-security-crypto 的 BCrypt |
| 测试 | JUnit 5 + MockMvc + 内嵌 MongoDB（de.flapdoodle.embed.mongo.spring31x） |

## 2. 功能清单

阶段一：

- 用户：注册、登录（JWT），只能看到并操作自己创建的问卷
- 问卷：创建、编辑（题目增删排序、选项、约束、跳转规则）、发布、设置截止时间、关闭、删除
- 分享：发布时生成 8 位 `shareCode`，分享链接 `http://<host>/s/{shareCode}`
- 题型：单选题、多选题、文本填空题、数字填空题；支持必答标记与约束参数
- 填写：逐题作答并即时保存草稿、按规则跳转、校验不通过即时提示、提交
- 统计：单选题各选项计数与总回答数；多选题各选项被选次数；文本题全部内容列表；数字题平均值/最小值/最大值

版本 2（题库）：

- 题库条目：单独建题、编辑、删除（被问卷引用时禁止删除）、标签
- 版本：每次内容变化产生新版本（v1 → v2 → …），历史链可追溯，可恢复旧版（以旧版内容生成最新版）
- 复用：问卷可从题库选题、可在问卷中直接建题并勾选“添加到题库”；同一题目可被多份问卷、以不同版本引用
- 共享：条目可共享到共享广场，其他用户可查看并引用当前版本；修改他人的共享题会在自己名下 fork 新条目
- 追踪：查看某题被哪些问卷使用、各自使用的版本
- 跨问卷统计：按版本分组聚合各问卷已提交答卷的回答
- 兼容：启动时自动把版本 1 的旧问卷题目迁移为题库条目 v1，幂等

## 4. 集合设计

五个集合：`users`、`surveys`、`responses`、`question_items`、`question_versions`。

### 4.1 users

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | ObjectId→String | 用户 id（JWT subject） |
| `username` | string | 用户名，**唯一索引** |
| `passwordHash` | string | BCrypt 哈希，永不存明文 |
| `createdAt` | date | 注册时间 |

索引：`username` 唯一。

### 4.2 surveys（问卷聚合根，题目与逻辑内嵌）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 问卷 id |
| `ownerId` | string | 创建者用户 id，**普通索引**（按人查列表） |
| `title` / `description` | string | 标题、说明 |
| `status` | string | `DRAFT` / `PUBLISHED` / `CLOSED` |
| `shareCode` | string | 8 位分享短码，**唯一索引**，发布时生成 |
| `settings` | object | `{allowAnonymous, allowMultiple, deadline}` |
| `questions` | array | 内嵌题目数组，数组顺序即默认答题顺序；元素是“引用 + 快照” |
| `logic` | array | 内嵌跳转规则数组 |
| `schemaVersion` | int | 结构版本号，当前 **2**（版本 1 由启动迁移升级） |
| `createdAt` / `updatedAt` | date | 时间戳 |

`questions[]` 元素：

| 字段 | 类型 | 说明 |
|---|---|---|
| `qid` | string | 题目在本卷内唯一标识 |
| `itemId` | string/null | 引用的题库条目 id（版本 2 新增；未入题库时为 null） |
| `versionId` | string/null | 引用的具体版本 id（版本 2 新增） |
| `version` | int/null | 引用版本号，便于展示与排查（版本 2 新增） |
| `type` | string | `single` / `multiple` / `text` / `number`（**字符串而非枚举**，便于扩展新题型） |
| `title` | string | 题干 |
| `required` | bool | 是否必答 |
| `options` | array | `[{oid, text}]`，仅选择题使用 |
| `constraints` | object | 题型约束，键由题型决定 |

> 引用字段之外的五项内容字段是**引用时刻的快照**：保存问卷时写入，之后不随题库版本变化；同时前端会带一个 `addToLibrary` 临时标志（`@Transient`，不落库），仅用于这一次保存决定“是否为该新题创建题库条目”。

`logic[]` 元素：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 规则唯一标识 |
| `when` | object | `{qid, op, value}`：对某题答案做运算 |
| `then` | object | `{action, targetQid}`：`action` 取 `jumpTo` / `end` |

### 4.3 responses（答卷）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 答卷 id |
| `surveyId` | string | 所属问卷 id，**普通索引** |
| `respondentId` | string/null | 填写人 id，匿名为 null |
| `status` | string | `DRAFT` / `SUBMITTED` |
| `answers` | array | 内嵌答案数组 |
| `currentQid` | string/null | 草稿续填位置 |
| `createdAt` / `submittedAt` | date | 开始时间 / 提交时间 |

`answers[]` 元素：`{qid, optionIds[], text, number}`。三个值字段按题型只会有一个非空，三者皆空表示未作答。这样设计的好处是**同一数组结构兼容四种题型**，增加题型也不需要改答卷结构。

### 4.4 question_items（题库条目，版本 2 新增）

条目只存元数据，**不存题目内容**；内容全部在 `question_versions` 中。

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 条目 id |
| `ownerId` | string | 所属用户，**普通索引**（“我的题库”列表） |
| `tags` | array | 标签列表 |
| `shared` | bool | 是否共享到共享广场 |
| `currentVersionId` | string | 当前版本 id（唯一的内容指针） |
| `copiedFromItemId` | string/null | fork 来源条目 id（引用他人共享题后修改时记录） |
| `createdAt` / `updatedAt` | date | 时间戳 |

索引：`ownerId`（按用户查列表）。

### 4.5 question_versions（题目版本，版本 2 新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 版本 id |
| `itemId` | string | 所属条目，**普通索引**（查版本链、按条目统计） |
| `version` | int | 版本号，从 1 递增 |
| `parentVersionId` | string/null | 父版本 id，v1 为 null，构成版本链 |
| `type` / `title` / `required` / `options` / `constraints` | — | 与 `surveys.questions[]` 内容字段完全一致，可直接转成问卷题目 |
| `note` | string | 本次修改说明（如“在问卷中修改”“恢复自 v1”“由旧版问卷迁移”） |
| `createdAt` | date | 创建时间 |

索引：`itemId` 普通索引；`{itemId: 1, version: 1}` **复合唯一索引**，保证同一题目下版本号不重复。

版本记录**创建后永不修改**，这是“修改题目不影响已做好的问卷”的根本保障。

## 5. 为什么这样设计

### 5.1 内嵌 vs 引用

- **题目、选项、跳转规则内嵌进 `surveys`**：问卷与其题目是强聚合关系，几乎总是整卷一起读写。内嵌后“取一份问卷”只查一次集合，无需 join，也保证题目顺序天然稳定（数组顺序即顺序）。
- **答卷内嵌 `answers`**：一份答卷是一份独立快照。答卷数量随填写增长，若把每条答案拆成独立集合会产生大量细碎文档。一份答卷一个文档，写入借 `_id` 定位，天然并发安全。
- **答卷引用问卷（`surveyId`）而非内嵌问卷**：问卷是“可变的定义”，答卷是“已发生的记录”。若把问卷整卷内嵌进每份答卷，问卷改动要更新所有答卷副本，冗余且危险。
- **题库独立成集合（版本 2）**：题目需要跨问卷复用、需要保留历史版本、需要被不同用户共享，这三件事都超出单份问卷的边界。若把版本历史内嵌在 `surveys` 里，同一道题被 10 份问卷引用就要存 10 份历史；把条目与版本放到独立集合后，内容只有一份，问卷侧只存引用与快照。

### 5.2 为什么不用关系数据库结构

- 问卷的题目、选项、约束、跳转规则结构灵活多变（题型不同字段不同、选项数量不定、约束键按题型不同）。关系库需要 `questions` / `options` / `constraints` / `logic_rules` 多张表加大量可空列或 EAV 表，加题型就要改表结构；MongoDB 用文档自然表达“一份问卷一段结构”，加题型只改文档内容不改 schema。
- 答卷同样：不同题型答案字段不同，关系库需要一张表+可空列或答案键值表；文档模型下 `answers` 数组直接承载多态答案。
- 版本化在关系库中同样可以建模（`item` + `version` 两表），但版本内容仍要拆成题型、选项、约束多表；文档模型下版本文档可直接复用题目结构，读写一份版本就是一次查询。
- 读写模式是“整卷读、整卷写”，与文档模型天然贴合。

### 5.3 冗余使用的克制

- `surveys.settings` 与题目同卷内嵌，属于聚合内部数据，不是冗余。
- **问卷题目保存快照是刻意的冗余**：快照让问卷与其历史答卷自洽，也避免展示问卷时再去题库拼装内容。代价是同一内容在问卷与版本中各存一份，但纠正方式是“只读快照、不写快照”（保存问卷时才更新引用），风险可控。
- **不做**跨集合冗余（例如不在答卷里存问卷标题），避免问卷改名后出现不一致副本；需要展示时按 `surveyId` 查问卷。
- 统计不落库、不预聚合：统计在查询时基于已提交答卷实时计算（当前数据规模下正确性优先，避免中间态数据不一致）。

### 5.4 版本不可变

修改题目 = 追加一个版本，旧版本原样保留。好处：

1. 引用旧版本的问卷内容永远可解释，历史答卷的统计口径不会漂移；
2. 版本链（`parentVersionId`）可完整还原修改过程；
3. “恢复旧版”只是以旧版内容再追加一个最新版本，不是回滚指针，因此不会让还引用中间版本的问卷突然改变语义。

## 6. 索引与约束

| 索引 | 作用 |
|---|---|
| `users.username`（unique） | 用户名唯一，注册查重、登录定位 |
| `surveys.ownerId` | “我的问卷”列表查询 |
| `surveys.shareCode`（unique） | 分享链接按码取卷；唯一索引同时兜底避免短码撞车 |
| `responses.surveyId` | 统计按问卷取全部已提交答卷、删除问卷时级联清理、续填查草稿 |
| `question_items.ownerId` | “我的题库”列表 |
| `question_versions.itemId` | 查某题的版本链、按条目统计 |
| `{itemId, version}`（unique） | 同一题目下版本号唯一，防止并发写入产生重复版本 |

应用层校验（不依赖数据库约束，因 Mongo 无跨文档约束）：题目 `qid` 唯一、选项 `oid` 唯一、题目标题非空、跳转规则目标必须存在且只能向后跳、题型约束自洽（如 `maxSelect <= 选项数`）；题库条目内容同样校验标题非空、`oid` 非空且唯一、题型约束自洽；非本人且未共享的条目拒绝访问；被问卷引用的条目禁止删除。

## 7. 旧数据迁移

`SchemaMigrationRunner`（`ApplicationRunner`）在启动时扫描 `schemaVersion < 2` 的问卷，为每道没有 `itemId` 的旧题创建题库条目与 v1（`note` 为“由旧版问卷迁移”），回填 `itemId/versionId/version`，然后把问卷置为 `schemaVersion = 2`。迁移幂等：已带引用的题目直接跳过，重复启动不会产生多余条目或版本。

## 8. 运行方式

```bash
# 1. 启动本地 MongoDB（服务名 MongoDB，默认 27017）
# 2. 启动应用
mvn spring-boot:run
# 3. 打开 http://localhost:8080/login 注册 → /surveys 创建问卷、/library 管理题库
```

配置见 `src/main/resources/application.yml`：MongoDB URI、JWT secret（应改用环境变量注入）、token 有效期 72h。

测试：

```bash
mvn test    # 自动启动内嵌 MongoDB，不依赖本地数据库
```
