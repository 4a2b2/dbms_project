# 07 题库与版本扩展（阶段二需求变更）

本文档对应《大作业一：需求变更》的八条扩展需求，说明设计决策、数据模型、接口与测试覆盖。

## 需求对照总览

| # | 需求 | 实现方式 |
|---|------|----------|
| 1 | 题目独立保存、可复用 | 新增题库集合 `question_items` + `question_versions`，问卷只存引用 + 快照 |
| 2 | 题目共享给其他用户 | 条目 `shared` 开关 + 共享广场，他人可引用但不可改 |
| 3 | 修改题目不影响已做好的问卷 | 版本不可变；问卷内嵌题目是引用时刻的内容快照，永不回写 |
| 4 | 记录修改历史、可恢复旧版 | 版本链 `parentVersionId`，恢复 = 以旧版内容创建最新版（不回滚历史） |
| 5 | 同一题目多版本并存、不同问卷用不同版本 | 每份问卷记录 `versionId`，版本记录永久保留 |
| 6 | 查看题目被哪些问卷使用 | `GET /api/items/{id}/usage` |
| 7 | 题库管理（管理/加入/选题/更新版本） | 题库页 `/library` + 编辑器内"从题库选择"；编辑器勾选「添加到题库」后保存入题库，引用题修改自动版本化 |
| 8 | 跨问卷查看单题总体统计 | `GET /api/items/{id}/stats`，按版本分组聚合，文本/数字题附跨版本总览 |

## 核心设计决策

### 1. 版本不可变（Immutability）

题目内容只能通过"创建新版本"演进，`question_versions` 中的任何版本记录创建后永不修改。
这是整个扩展的基石：只要旧版本还在，引用它的问卷内容就有据可查，天然满足需求三。

### 2. 问卷内嵌题目 = 引用 + 快照

`Question` 在原字段（type/title/required/options/constraints）之外新增三个引用字段：

```java
private String itemId;      // 题库条目
private String versionId;   // 引用的具体版本
private Integer version;    // 版本号（展示用）
```

原字段成为**引用时刻写入的内容快照**，发布后固化。好处是第一阶段的答卷校验、
跳转引擎、单卷统计、填写页全部零改动——它们只看问卷内嵌内容，不感知题库。
即使题库条目日后删除策略放开，历史问卷与答卷数据依然完整自洽。

### 3. 条目与内容分离

`question_items` 只存归属、标签、共享开关、当前版本指针等元数据，不存题目内容；
内容全部在版本里。因此"当前内容"永远等于 `currentVersionId` 指向的版本，不存在两份真相。

### 4. 编辑器体验不变，版本化发生在保存时

`SurveyService.resolveQuestions` 在保存问卷时逐题判定：

```
题目无 itemId 且勾选「添加到题库」 → 创建题库条目 + v1（新题入题库）
题目无 itemId 且未勾选            → 仅属于本问卷，不入题库
引用题且内容未变     → 沿用该版本引用
引用自己的题且内容变了 → 自动创建下一版本（parent = 当前版本），问卷引用新版本
引用别人的共享题且内容变了 → 自动 fork 为自己的新条目（记录 copiedFromItemId），原题不受影响
```

用户在问卷编辑器里改题不需要理解版本概念，系统静默完成正确的事。

### 5. 恢复旧版 = 新建版本，不做回滚

恢复操作以目标版本的内容创建一个最新版本（note 标记"恢复自 vN"）。
历史链保持完整的 v1 → v2 → v3 → v4，语义清晰，也不会让"引用 v3 的问卷"
突然变成别的内容。

### 6. 跨问卷统计按版本分组

同一题目的不同版本内容可能不同（选项增删、标题改写），直接合并会失真。
统计按版本分组聚合各版本的回答；仅当题型全程一致且为文本/数字题时，
额外提供跨版本总览（选择题选项 oid 可能随版本变化，不合并，只看分组）。

## 数据模型

### question_items（题目条目）

| 字段 | 说明 |
|------|------|
| _id | 条目 ID |
| ownerId | 创建者（索引） |
| tags | 标签数组 |
| shared | 是否共享 |
| currentVersionId | 当前版本指针 |
| copiedFromItemId | fork 来源条目（从共享题改造而来时记录） |
| createdAt / updatedAt | 时间戳 |

### question_versions（不可变版本，复合唯一索引 `{itemId:1, version:1}`）

| 字段 | 说明 |
|------|------|
| _id | 版本 ID |
| itemId | 所属条目（索引） |
| version | 版本号，从 1 递增 |
| parentVersionId | 上一版本 ID（v1 为 null），构成版本链 |
| type / title / required / options / constraints | 题目内容（与问卷内嵌字段一致） |
| note | 修改说明 |
| createdAt | 时间戳 |

### surveys 变更

- `questions[]` 元素新增 `itemId / versionId / version` 引用字段，其余字段为快照。
- `schemaVersion` 从 1 升级到 2。

### 旧数据迁移

`SchemaMigrationRunner`（ApplicationRunner）启动时扫描 `schemaVersion < 2` 的问卷，
为每道无引用的旧题创建条目 + v1（note="由旧版问卷迁移"）并回填引用，置 schemaVersion=2。
迁移幂等：已带 itemId 的题跳过，重复执行不会产生新版本。

## 接口一览（均需登录）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/items | 我的题库（附当前版本内容） |
| GET | /api/items/shared | 共享广场 |
| POST | /api/items | 新建题目（自动 v1） |
| GET | /api/items/{id} | 题目详情（owner 或共享可读） |
| PUT | /api/items/{id} | 修改题目：内容真的变化才创建新版本；只改标签不刷版本 |
| POST | /api/items/{id}/share | 共享开关 `{shared}` |
| DELETE | /api/items/{id} | 删除：被问卷引用时返回 409 |
| GET | /api/items/{id}/versions | 版本历史链 |
| POST | /api/items/{id}/restore | 恢复旧版 `{versionId}`（创建最新版） |
| GET | /api/items/{id}/usage | 被哪些问卷使用（含各卷引用的版本） |
| GET | /api/items/{id}/stats | 跨问卷统计（按版本分组 + 文本/数字总览） |

页面：新增题库页 `/library`；问卷编辑器新增"从题库选择"面板与题目的"题库 vN"徽标；
问卷列表顶部导航新增"题库"入口。

## 前端配合细节

- 题库编辑表单保留选项原 `oid`，内容未变的保存不会产生新版本；
  非单选题始终提交约束（空对象表示清空）。
- 编辑器选题面板合并展示"我的题库 + 共享广场（排除自己的）"，选用即引用当前版本；
  在编辑器中修改自己的题库题并保存，会自动产生新版本（后端判定，前端无额外逻辑）。
